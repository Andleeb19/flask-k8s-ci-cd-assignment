                         WORKFLOW SUMMARY

═══════════════════════════════════════════════════════════════

1. DEVELOPER writes code
   ↓
2. DEVELOPER pushes to feature branch
   ↓
3. DEVELOPER creates Pull Request to develop
   ↓
4. GITHUB ACTIONS automatically tests code (CI)
   ├─ Runs flake8 linting
   ├─ Runs pytest tests
   └─ Builds Docker image
   ↓
5. ADMIN reviews Pull Request
   ├─ Checks code quality
   ├─ Verifies tests passed
   └─ Approves or requests changes
   ↓
6. ADMIN merges to develop branch
   ↓
7. ADMIN creates PR from develop → main
   ↓
8. ADMIN merges to main branch
   ↓
9. JENKINS automatically deploys (CD)
   ├─ Builds Docker image
   ├─ Deploys to Kubernetes
   └─ Verifies deployment
   ↓
10. KUBERNETES runs the app
    ├─ 3 pods running
    ├─ Load balancing traffic
    ├─ Health monitoring
    └─ Auto-restart if crash
    ↓
11. USER accesses app via browser
    └─ http://MINIKUBE_IP:30080

                    KEY KUBERNETES FEATURES

═══════════════════════════════════════════════════════════════

🔄 ROLLING UPDATES
   Problem: How to update without downtime?
   Solution: Update pods one by one
   
   Old Version (3 pods)    Mixed (4 pods)      New Version (3 pods)
   🟦 🟦 🟦         →     🟦 🟦 🟩 🟩    →    🟩 🟩 🟩
   
   • maxSurge: 1 (can have 4 pods temporarily)
   • maxUnavailable: 1 (minimum 2 always running)

📊 SCALING
   Need more power? Just increase replicas!
   
   kubectl scale deployment --replicas=5
   
   Before:    After:
   🟩 🟩 🟩  →  🟩 🟩 🟩 🟩 🟩
   
   Need less? Decrease replicas!
   
   kubectl scale deployment --replicas=2
   
   Before:         After:
   🟩 🟩 🟩 🟩 🟩  →  🟩 🟩

⚖️ LOAD BALANCING
   Service distributes traffic evenly:
   
   User Requests      Load Balancer       Pods
        │                   │           
   ┌────┴────┐             │          ┌─────┐
   │Request 1│─────────────┼─────────►│Pod 1│
   └─────────┘             │          └─────┘
   ┌─────────┐             │          ┌─────┐
   │Request 2│─────────────┼─────────►│Pod 2│
   └─────────┘             │          └─────┘
   ┌─────────┐             │          ┌─────┐
   │Request 3│─────────────┼─────────►│Pod 3│
   └─────────┘             │          └─────┘

🏥 HEALTH CHECKS
   Kubernetes monitors pod health:
   
   Every 5 seconds: "Are you alive?"
   Pod: "Yes! /health returns 200 OK"
   
   If pod crashes:
   Kubernetes: "Pod 2 not responding!"
   ├─ Remove from load balancer
   └─ Start new pod automatically
   
   Result: Zero downtime!

🔙 ROLLBACK
   New version has bugs? Rollback instantly!
   
   Version 2 (buggy)          Version 1 (stable)
   🟥 🟥 🟥         →         🟩 🟩 🟩
   
   kubectl rollout undo deployment/flask-app-deployment

💾 RESOURCE MANAGEMENT
   Each pod guaranteed:
   • CPU: 100m (0.1 cores)
   • Memory: 128Mi
   
   Pod cannot exceed:
   • CPU: 500m (0.5 cores)
   • Memory: 256Mi
   
   Prevents one app from hogging all resources!

                    TECHNOLOGIES EXPLAINED

═══════════════════════════════════════════════════════════════

🐍 PYTHON + FLASK
   • Python: Programming language
   • Flask: Web framework (makes building APIs easy)
   
🐳 DOCKER
   • Packages app + dependencies into "container"
   • Like a lightweight virtual machine
   • Works same on any computer
   
☸️ KUBERNETES (K8s)
   • Orchestrates (manages) containers
   • Handles scaling, updates, health
   • Industry standard for production
   
🎯 MINIKUBE
   • Mini Kubernetes on your laptop
   • For testing before real cloud
   • Single-node cluster
   
🔧 KUBECTL
   • Command-line tool for Kubernetes
   • Like a remote control
   
🤖 JENKINS
   • Automation server
   • Runs deployment pipeline
   • Connects GitHub → Kubernetes
   
😺 GITHUB
   • Code storage + collaboration
   • Version control with Git
   
⚡ GITHUB ACTIONS
   • Cloud CI/CD (testing) service
   • Runs automatically on code push
   • Free for public repos

                    COMMON TERMINOLOGY

═══════════════════════════════════════════════════════════════

CI/CD:
  Continuous Integration + Continuous Delivery
  Automate testing and deployment

Container:
  Package containing app + dependencies

Image:
  Blueprint for creating containers
  (like a recipe)

Pod:
  Smallest unit in Kubernetes
  (usually 1 container)

Deployment:
  Manages a set of identical pods

Service:
  Load balancer for pods
  (single entry point)

Node:
  A machine (physical or virtual)
  Runs pods

Cluster:
  Set of nodes working together

Namespace:
  Virtual cluster within cluster
  (for organization)

Rolling Update:
  Gradual replacement of old pods
  with new ones (zero downtime)

Scaling:
  Changing number of pod replicas

Rollback:
  Reverting to previous version

Health Check:
  Automatic testing if pod is alive

Resource Limit:
  Max CPU/memory a pod can use

NodePort:
  Exposes service on static port
  (30000-32767)

Replica:
  Copy of a pod
